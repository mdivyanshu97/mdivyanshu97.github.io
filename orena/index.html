The project

One recipe.
Two video scales.

Short segments need precise local evidence; hour-long procedures need a search strategy. Both repositories share the surgical adaptation recipe, answer-format constraints, and absolute-time frame overlays.

01 / DISCOVR-SEGMENT

Short-video reasoning

One merged checkpoint answers segment questions. A predicted timestamp triggers a second look within ±15 seconds; timestamps stated in a question guide ±30-second evidence windows.

01 / Post-training

Learn the domain,
then learn the task.

I constructed surgical scene-literacy data from SSG-VQA and CholecT45, continued the adapters on joint FRAME, SEGMENT, and PROCEDURE supervision, and merged each selected adapter into its own bfloat16 model.

SVG figure PDF figure Segment method Procedure method

Build supervision carefully

Join surgical QA to source frames, de-duplicate records, normalize formats, and represent each example as image-conditioned chat.

Train the answer, not the prompt

Apply supervised cross-entropy to answer tokens, masking the system instruction, question, padding, and visual placeholders.

Match training and serving

Use chronological frames, a 768-pixel longest-side cap, and absolute video timestamps throughout temporal training and inference.

Training loss was monitored with row-random splits, so it is not a video-disjoint generalization estimate. This project uses supervised fine-tuning; the temporal search policy is deterministic.

02 / Inference

Answer.
Then zoom in.

A uniform pass can miss a brief event in a long video. I used the first prediction as a pointer, then resampled near it. Narrowing the interval improves temporal resolution with a bounded frame budget.

04 / Engineering

Make the work
inspectable.

I released the merged checkpoints, inference code, method descriptions, and container tooling. The public source can be reviewed and tested on CPU before running a full GPU smoke test.

  • Traceable model artifactsPinned Hugging Face revisions, SHA-256 checks, and preserved submission records.
  • Bounded GPU memoryProcedure runs W64 and NW2 in separate phases, with one model resident at a time.
  • Defensive batch executionOrdered atomic output, isolated question failures, and visible setup or write failures.
  • Checks that can run without a GPUFormat, routing, batch I/O, and release-integrity regressions, plus lint and shell checks.
